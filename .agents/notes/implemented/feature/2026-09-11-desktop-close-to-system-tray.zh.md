# Agent Note: 桌面应用关闭操作保留在系统托盘中

Status: implemented

[English](2026-09-11-desktop-close-to-system-tray.md) | 中文

## 问题

桌面壳承载的后端进程可以在窗口隐藏后继续为 Web UI 提供服务。把每次窗口关闭都视为进程退出，会阻止用户在只想关闭窗口时把会话保留在 Windows 通知区域中。

## 决策

主进程拦截窗口的 `close` 事件，并询问用户是最小化到系统托盘还是退出。最小化会隐藏窗口、按需创建托盘图标，并保持后端进程运行。托盘菜单可以恢复并聚焦窗口，也可以退出应用。已经开始的应用退出过程会跳过询问，并在清理阶段销毁托盘图标。再次启动应用时会恢复隐藏的窗口。

## 曾考虑的替代方案

- **窗口关闭始终退出** —— 否决，因为用户只想关闭窗口时，这会停止后端并丢失当前桌面会话。
- **窗口关闭始终最小化到托盘** —— 否决，因为用户需要一种明确且容易发现的方式来停止后端并退出应用。
- **持久化关闭行为偏好** —— 暂不采用，因为需求是每次关闭时明确选择，不需要新增设置约定。

## 后果

用户选择托盘后，应用会继续驻留，后端和会话状态会持续运行，直到用户从托盘菜单选择退出。原生关闭询问使用与现有桌面主进程对话框一致的英文标签。桌面主进程测试覆盖了关闭选择的两条路径。
